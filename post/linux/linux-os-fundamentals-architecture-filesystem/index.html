      리눅스(Linux) 운영체제 기초#

      리눅스의 탄생 배경과 역사#

      유닉스 (Unix)와 POSIX 표준#

      • 유닉스는 1969년 벨 연구소의 켄 톰프슨(Ken Thompson), 데니스 리치(Dennis Ritchie) 등이 주도하여 개발한 범용 다중 사용자(Multi-user) 시분할 운영체제입니다.
      • 여러 제조사가 각자의 유닉스 변형판을 개발하면서 호환성 문제가 대두되었고, 이를 해결하기 위해 IEEE에서 **POSIX(Portable Operating System Interface)**라는 이식 가능한 표준 운영체제 인터페이스 규격을 정의하였습니다.
      • 리눅스는 유닉스의 철학과 인터페이스를 계승하여 POSIX 호환을 따르도록 설계되었습니다.

      GNU 프로젝트와 GPL 라이선스#

      • 1983년 리처드 스톨먼(Richard Stallman)이 자유 소프트웨어 재단(FSF)을 설립하고, 누구나 자유롭게 사용·수정·배포할 수 있는 운영체제를 구축하기 위해 GNU(GNU’s Not Unix) 프로젝트를 시작하였습니다.
      • 소프트웨어의 자유를 보장하기 위해 GPL(General Public License) 라이선스를 제정하였으며, 주요 원칙은 다음과 같습니다.
        1. 프로그램을 어떤 목적으로든 자유롭게 실행할 수 있습니다.
        2. 소스코드를 연구하고 목적에 맞게 수정할 수 있습니다.
        3. 소프트웨어 복제본을 재배포할 수 있습니다.
        4. 수정된 프로그램을 재배포할 때는 동일한 GPL 라이선스로 소스코드를 반드시 공개해야 합니다.

      리누스 토르발스와 리눅스 커널#

      • 1991년 헬싱키 대학교 학생이던 리누스 토르발스(Linus Torvalds)가 개인용 PC(Intel 386)에서 동작하는 운영체제 커널을 독자 개발하여 공개하였습니다.
      • 완성된 GNU 시스템 유틸리티(컴파일러, 쉘 등)에 리눅스 커널이 결합되면서 오늘날의 완전한 GNU/Linux 운영체제가 완성되었습니다.
      • 커널은 동일하지만 패키지 관리자와 환경에 따라 Ubuntu, Debian, Red Hat Enterprise Linux(RHEL), Rocky Linux, Fedora, Arch Linux 등 다양한 배포판이 존재합니다.

      리눅스 시스템 계층 구조#

      리눅스는 계층화된 아키텍처를 통해 하드웨어 자원을 추상화하고 애플리케이션을 안전하게 격리합니다.

      +-------------------------------------------------+
|       사용자 애플리케이션 / 쉘 (Bash, Zsh)       |
+-------------------------------------------------+
|          시스템 유틸리티 및 표준 C 라이브러리      |
+-------------------------------------------------+
|          시스템 콜 인터페이스 (System Call)      |
+-------------------------------------------------+
|           리눅스 커널 (프로세스, 메모리, VFS)    |
+-------------------------------------------------+
|                하드웨어 (CPU, RAM, Disk, NIC)    |
+-------------------------------------------------+
      • 하드웨어에 가까울수록 저수준(Low-level) 특권을 가지며 커널 모드(Ring 0)에서 동작하고, 사용자 영역은 유저 모드(Ring 3)에서 동작하여 시스템 안정성을 보장합니다.

      파일 시스템 구조#

      • 리눅스는 최상위 루트 디렉터리(/)를 기점으로 하는 단일 트리(Tree) 구조를 형성합니다.
      • **모든 것은 파일이다(Everything is a file)**라는 유닉스 철학에 따라 일반 파일뿐 아니라 디렉터리, 소켓, 파이프, 하드웨어 장치(/dev)까지 파일 형태로 추상화하여 일관된 I/O 인터페이스로 제어합니다.

      파티션 블록 구성#

      일반적인 ext4 파일 시스템 파티션은 다음과 같은 논리 블록 집합으로 구성됩니다.

      +------------+-------------+---------------+---------------+
| Boot Block | Super Block |  i-node List  |   Data Blocks |
+------------+-------------+---------------+---------------+
      • 부트 블록 (Boot Block): 운영체제를 부팅하기 위한 부트스트랩 로더(Bootstrap Loader) 코드가 위치합니다.
      • 슈퍼 블록 (Super Block): 파일 시스템의 전체 크기, 마운트 상태, 자유 블록 수, 사용 가능한 i-node 수 및 블록 크기 등 파일 시스템의 핵심 메타 정보를 보관합니다.

      i-node (Information Node) 메타데이터#

      • 파일 시스템의 모든 파일과 디렉터리는 고유한 i-node 번호와 구조체에 1:1로 대응됩니다.
      • 디렉터리 엔트리는 파일 이름과 해당 i-node 번호의 매핑 쌍만 저장하며, 파일의 실제 모든 메타 정보는 i-node에 기록됩니다.
        1. 파일 소유자 UID 및 소유 그룹 GID
        2. 파일 유형 (일반 파일, 디렉터리, 심볼릭 링크 등)
        3. 접근 권한 (rwxrwxrwx)
        4. 타임스탬프 (atime: 최근 접근, mtime: 최근 수정, ctime: 상태 변경)
        5. 하드 링크 수 (nlink)
        6. 파일 크기 (바이트 단위)
        7. 실제 데이터가 저장된 데이터 블록의 디스크 주소 포인터
      • ls -li 명령어로 파일의 i-node 번호를 확인할 수 있습니다.

      데이터 블록 (Data Block)#

      • 실제 파일 내용이 저장되는 디스크 공간으로, 일반적으로 4KB 단위 블록으로 할당됩니다.

      리눅스 표준 디렉터리 구조 (FHS)#

      리눅스는 FHS(Filesystem Hierarchy Standard) 표준에 따라 디렉터리 용도를 규정합니다.

      • /bin: 일반 사용자가 실행할 수 있는 필수 기본 명령어 바이너리 (ls, cp, cat)
      • /sbin: 시스템 관리자(root)를 위한 필수 시스템 관리 명령어 (fdisk, reboot, iptables)
      • /boot: 리눅스 커널 이미지(vmlinuz) 및 GRUB 부트로더 설정 파일
      • /dev: 시스템에 연결된 하드웨어 디바이스 노드 파일 (/dev/sda, /dev/null, /dev/urandom)
      • /etc: 시스템 전역 환경 설정 파일 및 데몬 서비스 설정 (/etc/passwd, /etc/fstab)
      • /home: 일반 사용자별 개인 홈 디렉터리 (/home/username)
      • /root: 시스템 관리자(root) 전용 홈 디렉터리
      • /lib, /lib64: 시스템 실행 파일들이 필요로 하는 핵심 공유 라이브러리(*.so) 및 커널 모듈
      • /opt: 타사(Third-party) 상용 소프트웨어가 독립적으로 설치되는 디렉터리
      • /proc: 실행 중인 프로세스와 커널 상태를 나타내는 가상(Virtual) 파일 시스템
      • /sys: 커널의 디바이스 모델 및 하드웨어 구성 상태를 나타내는 가상 파일 시스템
      • /tmp: 임시 파일 저장 공간으로 시스템 재부팅 시 또는 주기적으로 정리됨
      • /usr: 시스템 운영에 필요한 보조 소프트웨어, 라이브러리, 헤더 파일, 매뉴얼 등을 보관
      • /var: 로그 파일(/var/log), 메일 스풀, 데이터베이스 등 런타임 가변 데이터 보관

      바이트 오더와 엔디안 (Endianness)#

      컴퓨터 메모리에 다중 바이트 데이터를 저장하는 방식을 바이트 순서(Byte Order) 또는 엔디안이라 부릅니다.

      • 최상위 바이트(MSB, Most Significant Byte): 숫자의 크기에 가장 큰 영향을 주는 상위 자릿수 바이트입니다.
      • 최하위 바이트(LSB, Least Significant Byte): 가장 작은 자릿수의 바이트입니다.
      • 예: 4바이트 정수 0x12345678 저장 방식
        • 리틀 엔디안 (Little-Endian): 하위 바이트(LSB)부터 낮은 메모리 주소에 저장 (78 56 34 12). x86-64 아키텍처 및 대부분의 리눅스 시스템이 채택합니다.
        • 빅 엔디안 (Big-Endian): 상위 바이트(MSB)부터 낮은 메모리 주소에 저장 (12 34 56 78). 네트워크 프로토콜(Network Byte Order) 및 일부 RISC 계열에서 사용됩니다.
      • 서로 다른 아키텍처 간 네트워크 소켓 통신 시 htonl(), ntohl() 등의 변환 함수를 통해 바이트 순서를 통일해야 합니다.
