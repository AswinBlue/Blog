AWS 핵심 인프라 구축 가이드#

AWS 로그인#

  1. root 로그인과 IAM 로그인이 있다. 필요한 권한만 할당된 IAM 계정을 사용하는 것이 안전하며, root는 외부로 공유되지 않게 하고 보안을 철저히 한다.

Windows 서버 생성#

Windows 서버 vs Linux 서버

  • 중소기업 쪽에서는 보안 및 관리 요소가 줄어드는 Windows 서버를 선호하는 경우가 있다.
  • t 시리즈는 범용 서버이다. t2.large는 비교적 규모가 큰 인스턴스이다.
  • 프리티어를 사용하면 일부 서비스를 무료로 사용할 수는 있지만 성능에 제약이 있다.

  1. 좌측 상단 ‘서비스’를 선택하고 EC2를 검색하여 진입한다.

    • 기본으로 ‘대시보드’에 접근된다.
    • 리소스는 현재 계정에서 사용 중인 제품 현황을 나타낸다.
    • 기본 보안 그룹(Security Group)이 할당되어 있으며, 이는 일종의 인스턴스 방화벽 역할을 한다.

  2. 좌측 메뉴에서 ‘인스턴스’를 클릭한다.

    • 생성된 인스턴스 목록을 확인할 수 있다.
    • 주황색 ‘인스턴스 시작’ 버튼을 누른다.
    • 설정 단계를 거쳐 생성을 진행한다.
    1. AMI 선택
      • Windows Server 이미지를 선택한다. (업데이트에 따라 ID가 변경될 수 있으므로 이름을 확인)
      • ‘프리티어 사용 가능’ 태그를 확인한다.
      • AMI는 OS 및 기본 설정값을 포함하는 패키지 이미지이다.
    2. 인스턴스 유형 선택
      • 인스턴스 패밀리 및 세대를 선택한다. (테스트 시 프리티어 t2.micro 또는 성능에 따라 t2.large 등 선택)
      • CPU 크레딧 정책 및 시간당 비용을 확인한다.
    3. 인스턴스 세부 정보 구성
      • 인스턴스 개수, 네트워크(VPC) 및 서브넷을 지정한다.
      • 퍼블릭 IP 자동 할당 여부를 활성화한다.
      • IAM 역할, 종료 방지 기능 등의 옵션을 지정한다.
    4. 스토리지 추가
      • Windows 서버는 기본 EBS 볼륨으로 30GB가 제공된다. (Linux는 기본 8GB)
      • 볼륨 유형(범용 SSD gp2/gp3, 프로비저닝된 IOPS 등)을 선택한다.
      • ‘종료 시 삭제’ 옵션을 통해 인스턴스 종료 시 볼륨 보존 여부를 제어할 수 있다.
    5. 태그 추가
      • 다수의 인스턴스를 관리하기 위해 Name: WebServer-Win과 같이 Key-Value 태그를 지정한다.
    6. 보안 그룹 구성
      • 인스턴스 인바운드 트래픽을 제어하는 방화벽 규칙을 구성한다.
      • Windows 접속을 위한 RDP(원격 데스크톱 프로토콜, 포트 3389) 규칙을 추가한다. (보안을 위해 특정 IP 대역으로 제한 권장)
    7. 검토 및 키 페어 생성
      • 인스턴스를 시작할 때 RSA 키 페어를 새로 생성하거나 기존 키를 선택한다.
      • 다운로드된 .pem 프라이빗 키는 관리자 암호 해독에 필수적이므로 안전한 곳에 보관한다.

  3. RDP를 이용한 Windows 서버 접속

    1. EC2 인스턴스를 선택하고 상단 ‘연결’ 메뉴에서 ‘RDP 클라이언트’ 탭을 선택한다.
    2. 원격 데스크톱 파일(.rdp)을 다운로드한다.
    3. ‘암호 가져오기’를 클릭하고 다운로드해 둔 .pem 키를 업로드한 후 ‘암호 해독’을 수행한다.
    4. 해독된 암호를 복사하고 .rdp 파일을 실행하여 원격 데스크톱에 접속한다.

  4. 시스템 정보 확인

    • 접속 후 우측 상단의 EC2 인스턴스 정보(호스트 이름, 사설 IP, 공인 IP)를 확인한다.
    • Disk Management를 실행하여 연결된 스토리지 상태를 점검한다.

  5. 추가 디스크 설정

    • 추가된 EBS 볼륨이 Offline 상태인 경우 우클릭하여 Online으로 전환하고 디스크를 초기화(MBR 또는 GPT)한다.
    • ‘새 단순 볼륨’을 생성하여 드라이브 문자를 할당하고 포맷을 완료한다.

  6. 인스턴스 종료 (Terminate)

    • 인스턴스 상태에서 ‘종료’를 누르면 인스턴스가 영구 삭제 절차를 밟는다.
    • ‘종료 시 삭제’가 체크되지 않은 추가 EBS 볼륨은 남아있으므로 ‘Elastic Block Store’ -> ‘볼륨’ 메뉴에서 수동으로 정리한다.

  7. 요금 확인

    • AWS Billing 대시보드에서 일별/월별 발생 비용을 모니터링한다.

Linux 서버 생성#

  1. 인스턴스 생성

    1. AMI 선택: Amazon Linux 2 AMI 또는 Ubuntu LTS 선택
    2. 인스턴스 타입 선택: t2.micro 등 지정
    3. 세부 설정 및 스토리지 구성 (기본 8GB)
    4. 보안 그룹 구성: SSH(포트 22) 인바운드 허용
    5. 키 페어 설정 및 인스턴스 기동

  2. 서버 접속

    • Linux 서버는 SSH 프로토콜로 접속한다.
    • Linux/macOS 터미널:
      ssh -i "AWS_EC2_KEY.pem" ec2-user@<퍼블릭_IPv4_DNS>
    • Windows Putty 사용 시:
      1. PuTTYgen을 실행하여 .pem 파일을 불러온 후 .ppk 파일로 변환 저장
      2. PuTTY 실행 -> Connection > SSH > Auth에서 생성된 .ppk 키 등록
      3. Host Name에 EC2 인스턴스의 퍼블릭 IP를 입력하고 접속 (기본 계정: ec2-user 또는 ubuntu)

키 페어 가져오기#

  • 로컬에서 생성한 기존 SSH 공개키를 AWS로 등록하여 인스턴스에 적용할 수 있다.
  • EC2 대시보드의 네트워크 및 보안 > 키 페어 메뉴에서 ‘키 페어 가져오기’를 통해 공개키를 등록한다.

인스턴스를 AMI 이미지로 제작#

  1. AMI를 이용한 인스턴스 백업
    • 대상 인스턴스 우클릭 -> 이미지 및 템플릿 > 이미지 생성
    • 이미지 이름을 지정하면 인스턴스 상태를 그대로 담은 커스텀 AMI가 생성된다.
  2. 백업한 AMI를 다른 리전으로 복사
    • 생성된 AMI 우클릭 -> AMI 복사를 선택하고 대상 리전을 지정하여 이전할 수 있다.
  3. 다른 AWS 계정으로 AMI 공유
    • AMI 우클릭 -> AMI 권한 수정에서 대상 계정 ID를 등록한다.

커스텀 AMI로 EC2 시작#

  • AMI 메뉴에서 저장된 커스텀 이미지를 선택하고 우클릭 -> ‘시작하기’를 누르면 저장된 환경 그대로 인스턴스가 생성된다.

EBS 볼륨 생성 및 연결#

  1. 볼륨 생성: EBS 볼륨 메뉴에서 크기 및 가용 영역(AZ)을 지정하여 생성한다.
  2. 볼륨 연결:
    • 생성된 볼륨 우클릭 -> ‘볼륨 연결’ -> 동일 가용 영역 내 인스턴스 선택
    • Linux 인스턴스 내부에서 마운트 작업 수행:
      # 파일 시스템 포맷
sudo mkfs -t ext4 /dev/xvdf
# 마운트 포인트 생성 및 연결
sudo mkdir -p /mnt
sudo mount /dev/xvdf /mnt
# 확인
df -h

EBS 스냅샷 관리#

  • EBS 볼륨 상태를 특정 시점 기준으로 백업하는 스냅샷 생성 지원
  • 스냅샷을 기반으로 신규 EBS 볼륨을 복원하거나 새로운 AMI 이미지 생성 가능
  • 스냅샷 복사 기능을 통해 타 리전으로 데이터 이전 지원

S3 스토리지 생성 및 관리#

  1. S3 버킷 생성
    • 전 세계에서 고유한 버킷 이름을 지정하고 리전을 선택한다.
    • 정적 웹사이트 또는 외부 공개가 필요한 경우 ‘퍼블릭 액세스 차단’ 설정을 용도에 맞게 조정한다.
  2. 객체 업로드 및 권한 설정
    • 파일 및 폴더를 드래그앤드롭하여 업로드한다.
    • S3 URI는 AWS 내부 경로이며, 객체 URL은 가상 호스팅 기반 외부 접근 경로이다.
    • 퍼블릭 조회가 필요한 객체는 작업 메뉴에서 ‘퍼블릭으로 설정’을 지정한다.

로컬 파일 자동 백업 (AWS CLI)#

  1. IAM 콘솔에서 프로그래밍 방식 액세스 키(Access Key ID, Secret Access Key)를 발급받는다.
  2. 로컬 콘솔에서 aws configure 명령을 실행하여 인증 정보를 등록한다.
  3. S3 동기화 명령 실행:
    aws s3 sync ./backup_local s3://my-backup-bucket/backup/

S3 정적 웹사이트 호스팅#

  1. 퍼블릭 읽기 권한을 허용한 버킷을 생성한다.
  2. 버킷 ‘속성’ 탭에서 ‘정적 웹사이트 호스팅’을 활성화하고 인덱스 문서(index.html)를 지정한다.
  3. 버킷 정책(Bucket Policy)을 설정하여 익명 사용자의 읽기(s3:GetObject) 권한을 부여한다.

CloudFront CDN 연동#

  1. CloudFront 콘솔에서 ‘배포 생성(Create Distribution)‘을 선택한다.
  2. 원본 도메인(Origin domain)으로 S3 버킷을 지정한다.
  3. ‘기본 루트 객체(Default root object)‘에 index.html을 등록한다.
  4. 배포 완료 후 제공되는 CloudFront 도메인(*.cloudfront.net)을 통해 글로벌 캐싱 콘텐츠를 서빙한다.
  5. 파일 변경 시 ‘무효화 생성(Create Invalidation)’ 메뉴에서 캐시를 갱신할 수 있다.

EFS(Elastic File System) 연동#

  1. EFS 파일 시스템 생성: VPC 및 가용 영역별 탑재 대상을 지정한다.
  2. EC2 보안 그룹에서 EFS 인바운드 포트(NFS 2049)를 허용한다.
  3. 인스턴스 내부에서 EFS 마운트:
    sudo yum install -y amazon-efs-utils
sudo mkdir -p /mnt/efs/fs1
sudo mount -t efs -o tls fs-xxxxxx:/ /mnt/efs/fs1
df -h

RDS MySQL 데이터베이스 구축#

  1. RDS 콘솔에서 데이터베이스 생성을 클릭한다.
  2. 엔진으로 MySQL을 선택하고 인스턴스 클래스, 마스터 사용자 이름 및 암호를 설정한다.
  3. 외부 클라이언트 연결이 필요한 경우 ‘퍼블릭 액세스’를 허용하고 3306 포트를 보안 그룹에서 개방한다.
  4. MySQL Workbench를 사용하여 RDS 엔드포인트와 포트(3306)로 접속을 검증한다.

DynamoDB NoSQL 데이터베이스#

  1. DynamoDB 콘솔에서 테이블을 생성하고 파티션 키(Partition Key) 및 정렬 키(Sort Key)를 정의한다.
  2. ‘항목’ 탭에서 데이터를 JSON 기반 Key-Value 형태로 입력한다.
  3. 추가 인덱스 탐색이 필요한 경우 GSI(Global Secondary Index)를 구축하여 쿼리 성능을 최적화한다.

VPC 네트워크 설계 및 구축#

VPC 마법사를 활용한 자동 구성#

  • 탄력적 IP(EIP)를 할당받은 후 VPC 마법사를 실행하여 Public/Private 서브넷, NAT 게이트웨이, 라우팅 테이블을 자동으로 프로비저닝한다.

VPC 수동 구성 절차#

  1. VPC 생성: CIDR 블록(예: 10.0.0.0/16) 지정
  2. 서브넷 생성: Public 서브넷(10.0.1.0/24) 및 Private 서브넷(10.0.2.0/24) 분리
  3. 인터넷 게이트웨이(IGW) 생성 후 VPC에 연결(Attach)
  4. Public 라우팅 테이블 생성: 0.0.0.0/0 경로를 인터넷 게이트웨이로 전달하고 Public 서브넷에 연결
  5. NAT 게이트웨이 생성: Public 서브넷에 탄력적 IP와 함께 배치
  6. Private 라우팅 테이블 생성: 0.0.0.0/0 경로를 NAT 게이트웨이로 전달하고 Private 서브넷에 연결

VPC 피어링 (VPC Peering)#

  • 서로 다른 VPC 간의 내부 사설 네트워크 통신을 위해 피어링 연결을 구성한다.
  • 요청 VPC에서 피어링을 생성하고, 수락 VPC에서 요청을 승인한 후 양측 라우팅 테이블에 상대방 CIDR 대역 경로를 등록한다.

Route 53 도메인 관리 및 S3 연동#

  1. Route 53에서 도메인을 구매하거나 호스팅 영역(Hosted Zone)을 생성한다.
  2. A 레코드 생성: S3 정적 웹사이트 엔드포인트에 대한 별칭(Alias) 모드로 루트 도메인을 연결한다.
  3. CNAME 레코드 생성: www 서브도메인을 리다이렉션 전용 S3 버킷 또는 CDN 주소로 매핑한다.

Elastic Load Balancer (ALB) 구성#

  1. 다중 가용 영역(AZ)에 각각 Public 서브넷을 구성한다.
  2. 각 서브넷에 웹 서버 EC2 인스턴스를 기동하고 보안 그룹을 설정한다.
  3. Application Load Balancer(ALB) 생성:
    • HTTP 80번 포트를 리스너로 등록하고 대상 그룹(Target Group)을 생성한다.
    • 대상 그룹에 두 대의 EC2 인스턴스를 등록하고 헬스 체크(Health Check)를 설정한다.
  4. ALB DNS 주소로 접속하여 트래픽이 라운드로빈 방식으로 각 인스턴스에 분산되는지 확인한다.
  5. 세션 고정이 필요한 경우 대상 그룹 속성에서 Stickiness(고정 세션) 옵션을 활성화한다.

EC2 Auto Scaling#

  1. 시작 템플릿(Launch Template) 생성: AMI, 인스턴스 유형(t2.micro), 보안 그룹을 정의한다.
  2. Auto Scaling 그룹 생성:
    • 최소, 기본, 최대 인스턴스 용량을 지정한다.
    • CPU 사용률 목표 기반의 대상 추적 조정 정책(Target Tracking Policy)을 설정한다.
  3. 부하 테스트:
    • 인스턴스 내부에서 stress -c 1 명령으로 인위적 CPU 부하를 발생시켜 Scale-out(인스턴스 자동 추가) 동작을 검증하고, 프로세스 종료 시 Scale-in(인스턴스 자동 축소) 과정을 확인한다.

CloudFormation (IaC)#

  • 템플릿 파일(.yaml 또는 .template)에 인스턴스, 보안 그룹, 네트워크 아키텍처를 코드로 선언하여 동일한 인프라 스택을 재현 가능하게 자동 배포한다.

IAM 보안 권한 관리#

  1. IAM 사용자 및 그룹 생성: 최소 권한 원칙(Least Privilege)에 따라 필요한 정책(Policy)만 부여한다.
  2. IAM 역할(Role) 생성 및 EC2 인스턴스 프로파일 할당:
    • 하드코딩된 API Key 없이 EC2 인스턴스가 안전하게 S3나 DynamoDB 리소스에 접근할 수 있도록 IAM Role을 부여한다.

CloudWatch 모니터링 및 알람#

  1. EC2 인스턴스의 세부 모니터링을 활성화한다.
  2. CPU 사용률 지표를 기준으로 임계치 초과 시 SNS(Simple Notification Service)를 통해 이메일 알림이 전송되도록 경보(Alarm)를 구성한다.
