      VirtualBox 우분투 가상머신 root 비밀번호 재설정 및 복구 모드 진입 방법

      VirtualBox 우분투 root 비밀번호 복구 가이드 문제 상황 및 원인 VirtualBox에서 우분투(Ubuntu) 가상머신 이미지를 새로 생성하거나 사전 구성된 VDI 이미지를 불러올 때, 기본 생성된 사용자 계정(예: vboxuser)에 sudo 관리자 권한이 부여되어 있지 않거나 패스워드가 올바르지 않아 패키지 설치 및 시스템 설정을 진행하지 못하는 문제가 발생할 수 있습니다. 이러한 경우 GRUB 부트로더의 복구 모드(Recovery Mode)를 통해 관리자 권한을 복구할 수 있습니다. GRUB 복구 모드를 통한 해결 절차 1. GRUB 부팅 메뉴 진입 VirtualBox 관리자 창에서 해당 우분투 가상머신을 시작합니다. 가상머신 화면이 켜지는 즉시 키보드의 Shift 키(UEFI 시스템인 경우 ESC 키)를 연속으로 누르고 있어 GRUB 부트로더 화면을 호출합니다. 2. 리커버리 모드 (Recovery Mode) 선택 GRUB 메뉴 화면이 나타나면 Advanced options for Ubuntu 항목으로 이동하여 Enter를 입력합니다. 표시되는 커널 목록 중 끝에 (recovery mode)가 명시된 최신 커널 버전을 선택하여 부팅합니다. 3. root 쉘 프롬프트 진입 및 비밀번호 변경 복구 메뉴(Recovery Menu) 화면이 나타나면 방향키로 root (Drop to root shell prompt) 항목을 선택하고 Enter를 누릅니다. 화면 하단에 root 쉘 프롬프트가 열리면, 기본 읽기 전용(Read-Only)으로 마운트된 루트 파일 시스템을 쓰기 가능하도록 다시 마운트합니다. mount -o remount,rw / passwd 명령어로 root 관리자 계정의 비밀번호를 새로 설정합니다. passwd root 4. 일반 사용자 계정에 sudo 권한 부여 root 계정의 비밀번호 설정과 더불어, 기본 사용자(vboxuser)를 sudo 관리자 그룹에 추가해 두면 향후 편리하게 관리자 명령을 실행할 수 있습니다. ...

      우분투 apt 및 dpkg 오류 트러블슈팅 장애 발생 배경 Linux 서버에 개발 환경을 구성하던 중 패키지 설정이 꼬여 원격으로 외부 지원을 요청하였으나, 작업 과정에서 시스템 파일이 잘못 수정되어 APT 패키지 매니저가 완전히 동작을 멈추는 장애가 발생하였습니다. 본 글에서는 해당 장애의 발생 원인과 복구 절차를 정리합니다. 오류 원인 분석 /bin 디렉터리 내의 파이썬 실행 바이너리(python)를 강제로 임의 삭제한 것이 주원인으로 분석되었습니다. 패키지 의존성이 꼬인 상태에서 sudo apt-get upgrade 명령을 무리하게 남용하여 의존성 충돌이 가중되었습니다. 우분투의 다수 시스템 패키지 관리 스크립트(py3compile, py3clean)는 시스템 기본 파이썬 인터프리터에 의존하므로, 파이썬 인터프리터가 부재하면 패키지 설정 단계에서 치명적인 실패가 발생합니다. 장애 현상 apt install 또는 apt remove 명령을 실행할 때마다 py3compile, py3clean 단계에서 예외가 발생하였습니다. APT 작업 시 다음과 같은 에러가 반복 출력되며 정상적인 패키지 작업이 중단되었습니다. /usr/bin/dpkg returned an error code (1) apt-get install -f (broken dependency fix) 명령을 시도해도 동일한 에러 코드를 반환하며 복구되지 않았습니다. 단계별 복구 및 해결 방법 파이썬 환경 임시 복구 파이썬 실행 바이너리가 소실되어 관련 에러가 발생했으므로, 소스코드를 직접 빌드하거나 유효한 파이썬 바이너리를 다운로드하여 /usr/bin/python3 심볼릭 링크를 임시 복구하였습니다. 손상된 dpkg 패키지 메타데이터 확인 /var/lib/dpkg/info/ 디렉터리에는 시스템에 설치된 각 패키지의 설치/삭제 스크립트(*.postinst, *.prerm 등)가 저장되어 있습니다. 오류 로그에 명시된 특정 문제 패키지 목록을 파악한 후, 해당 패키지와 연관된 스크립트 파일을 안전하게 백업 및 삭제하였습니다. sudo rm /var/lib/dpkg/info/<문제가_발생한_패키지_이름>.* dpkg 상태 재구성 손상된 스크립트를 제거한 후 다음 명령으로 미완료 상태의 패키지 구성을 재설정하였습니다. sudo dpkg --configure -a APT 의존성 최종 정리 dpkg 재구성을 반복 수행하여 에러가 더 이상 발생하지 않을 때까지 문제 패키지를 정리한 후 정상적인 패키지 관리가 가능해졌습니다. sudo apt-get update && sudo apt-get -f install 교훈 및 요약 /bin, /usr/bin 등 운영체제 핵심 실행 파일이 위치한 디렉터리의 파일을 수동으로 임의 삭제하면 패키지 매니저 전체가 손상될 수 있으므로 절대 임의 삭제하지 말아야 합니다. 설치된 패키지 메타 정보는 /var/lib/dpkg/info/ 경로에 저장되며, 개별 패키지 스크립트 결함 시 해당 경로를 점검할 수 있습니다. 의존성 충돌 및 패키지 설치 중단 상태는 dpkg --configure -a 명령어로 재설정할 수 있습니다.
