      리눅스 프로세스 간 통신(IPC) 기법 총정리: 시그널, 파이프, 메시지 큐, 세마포어, 공유 메모리

      리눅스 프로세스 간 통신 (IPC: Inter-Process Communication) 시그널 (Signal) 시그널은 프로세스 간 동기화 및 이벤트 전달을 위해 커널 또는 프로세스 간에 전송하는 비동기 신호입니다. 소프트웨어 인터럽트(Software Interrupt)라고도 부릅니다. 쉘에서는 kill -<SIGNAL_NUMBER> <PROCESS_ID> 명령으로 특정 프로세스 ID에 시그널을 전달할 수 있습니다. 시그널은 총 64번까지 정의되어 있으며, 131번이 표준 POSIX 시그널이고, 3463번은 실시간(Real-Time) 고성능 처리를 위한 시그널입니다 (32, 33번은 미정의). kill -l 명령어로 시스템에 정의된 시그널 목록을 확인할 수 있습니다. SIGHUP (1): 터미널 접속 종료 시 전달되는 신호 SIGINT (2): 인터럽트, 키보드 Ctrl+C 입력 시 발생 SIGQUIT (3): 종료 및 코어덤프(Core dump) 생성 SIGILL (4): 유효하지 않은 명령어 실행 (Illegal instruction) SIGTRAP (5): 디버거 트레이싱 트랩 SIGABRT (6): abort() 함수 호출 시 프로세스 비정상 종료 SIGBUS (7): 버스 에러 (잘못된 메모리 접근) SIGFPE (8): 부동 소수점 산술 예외 (Floating point exception) SIGKILL (9): 프로세스 강제 종료 (무시 및 catch 불가) SIGUSR1 (10): 사용자 정의 시그널 1 SIGSEGV (11): 세그멘테이션 오류 (유효하지 않은 가상 메모리 참조) SIGUSR2 (12): 사용자 정의 시그널 2 SIGPIPE (13): 읽기 대상이 없는 파이프(Broken pipe)에 쓰기 시도 시 발생 SIGALRM (14): alarm() 타이머 만료 시 발생하는 시그널 SIGTERM (15): 정상적인 종료 요청 시그널 (소프트웨어 종료 신호) SIGSTKFLT (16): 스택 오류 (Stack fault) SIGCHLD (17): 자식 프로세스가 종료 또는 정지될 때 부모 프로세스에 전달 SIGCONT (18): 정지된 프로세스를 다시 재개(Continue)시키는 신호 SIGSTOP (19): 프로세스 실행 일시 정지 (무시 및 catch 불가) SIGTSTP (20): 터미널 정지 시그널, 키보드 Ctrl+Z 입력 시 발생 SIGTTIN (21): 백그라운드 프로세스가 터미널 입력(read)을 시도할 때 발생 SIGTTOU (22): 백그라운드 프로세스가 터미널 출력(write)을 시도할 때 발생 SIGURG (23): 긴급 소켓 데이터 수신 (Out-Of-Band) SIGXCPU (24): 설정된 CPU 시간 제한 초과 시 발생 SIGXFSZ (25): 허용된 파일 크기 한도 초과 시 발생 SIGVTALRM (26): 가상 타이머 만료 시그널 SIGPROF (27): 프로파일링 타이머 만료 시그널 SIGWINCH (28): 터미널 윈도우 크기 변경 시 발생 SIGIO / SIGPOLL (29): 비동기 I/O 이벤트 발생 가능 상태 SIGPWR / SIGLOST (30): 시스템 전원 장애 발생 SIGSYS (31): 잘못된 시스템 콜 호출 시 발생 C 언어 시그널 라이브러리 <signal.h>에 정의된 함수를 통해 시그널을 무시(SIG_IGN)하거나 핸들러 함수를 등록(SIG_DFL 또는 커스텀 핸들러)하여 가로챌 수 있습니다. 별도의 처리가 되지 않은 시그널을 수신하면 기본 동작(대부분 프로세스 종료)이 수행됩니다.       리눅스 프로세스 (Process) 심층 분석 프로그램과 프로세스의 기본 개념 프로그램(Program): 보조기억장치(디스크)에 정적으로 저장되어 있는 실행 가능한 바이너리 파일입니다. 프로세스(Process): 실행을 위해 메모리에 로드되어 운영체제로부터 CPU 스케줄링과 시스템 자원을 할당받아 실행 중인 인스턴스입니다. C 프로그램의 빌드 및 로딩 과정 C 언어 소스코드가 프로세스로 실행되기까지는 다음 4단계를 거칩니다. 전처리(Preprocessing): #include, #define 등 매크로 및 지시어를 확장합니다. 컴파일(Compilation): C 고수준 언어를 타깃 아키텍처의 어셈블리어로 변환합니다. 어셈블(Assembly) & 링크(Linking): 어셈블리어를 기계어 오브젝트 파일(.o)로 만들고, 라이브러리 및 타 오브젝트 심볼을 연결하여 ELF 실행 파일을 생성합니다. 로딩(Loading): 커널이 execve() 시스템 콜을 통해 가상 메모리 공간을 구성하고 바이너리를 로드하여 프로세스로 활성화합니다. 프로세스 복제와 생명주기 제어 프로세스 생성과 종료 대기 (fork & wait) pid_t fork(void): 부모 프로세스의 가상 주소 공간, 파일 디스크립터 테이블, 실행 문맥을 그대로 복제하여 새로운 자식 프로세스를 생성합니다. 반환값: 자식 프로세스에는 0, 부모 프로세스에는 자식의 PID(양수), 실패 시 -1을 반환합니다. fork() 직후 부모와 자식은 독립적으로 병행 실행되므로 스케줄링 순서를 보장할 수 없는 **경쟁 상태(Race Condition)**가 발생할 수 있습니다. pid_t wait(int *wstatus): 자식 프로세스가 종료될 때까지 부모 프로세스의 실행을 블록(대기)하고 자식의 종료 상태 코드를 수거합니다. 상태 값 비트 구조: 정상 종료 시: 종료 코드 값(exit(code))이 상위 8비트에 저장됩니다. 매크로 WIFEXITED(status), WEXITSTATUS(status)로 확인합니다. 비정상 종료 시: 프로세스를 종료시킨 시그널 번호가 하위 7비트에 저장됩니다. 매크로 WIFSIGNALED(status), WTERMSIG(status)로 확인합니다. 가상 메모리와 Copy-on-Write (COW) fork()가 발생하더라도 코드 영역(Text Segment)은 읽기 전용(Read-Only)이므로 부모와 자식이 동일한 물리 메모리 페이지를 공유합니다. 데이터 및 힙/스택 영역 또한 복제 시점에 물리 메모리를 즉시 복사하지 않고 동일 페이지를 읽기 전용으로 공유하다가, 둘 중 하나가 쓰기(Write) 작업을 시도하는 순간 페이지 폴트(Page Fault)가 발생하여 해당 페이지만 별도로 복제하는 Copy-on-Write (COW) 메커니즘을 사용합니다. 이를 통해 프로세스 생성 비용과 메모리 낭비를 극적으로 줄입니다. 좀비 프로세스와 고아 프로세스 방지 좀비 프로세스 (Zombie Process): 자식 프로세스가 exit()을 호출하여 실행을 마쳤으나, 부모 프로세스가 wait() 시스템 콜을 호출하여 자식의 종료 상태를 회수하지 않은 상태입니다. 프로세스 테이블 엔트리와 PID 자원을 계속 점유하여 누적 시 시스템 PID 고갈을 유발합니다. 고아 프로세스 (Orphan Process): 자식 프로세스보다 부모 프로세스가 먼저 종료된 경우입니다. 리눅스 커널은 고아 프로세스를 감지하면 최상위 부모인 init 프로세스(PID 1) 또는 systemd의 자식으로 재할당(Adopt)하여 자식이 종료될 때 자동으로 wait()을 수행해 좀비 상태가 되는 것을 방지합니다. 비동기 SIGCHLD 시그널과 넌블로킹 회수 부모 프로세스가 동기적으로 wait()에서 대기하지 않고 본연의 작업을 수행하면서 자식을 안전하게 정리하려면 SIGCHLD 핸들러를 사용합니다. ...

EOF(파일의 끝) 값은 -1로 정의되어 있습니다. 바이너리 파일 내의 0xFF 바이트와 EOF를 명확히 구분하기 위해 반환 타입으로 char 대신 4바이트 int를 사용합니다. fgets(char *s, int size, FILE *stream): 지정한 크기 또는 개행 문자(\n)를 만날 때까지 행 단위로 문자열을 읽어옵니다. fputs(const char *s, FILE *stream): 문자열을 파일 스트림으로 출력합니다.
