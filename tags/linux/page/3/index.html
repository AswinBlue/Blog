      Linux

      실무 리눅스 필수 명령어 가이드: sed·tr 텍스트 조작, tar 압축, ELF 바이너리 분석 및 리다이렉션

      리눅스 필수 명령어 가이드 환경 변수와 PATH 관리 리눅스 기본 시스템 명령어들은 /usr/bin/, /bin/, /usr/local/bin/ 디렉터리에 위치하며 일반 사용자에게 실행 권한이 부여되어 있습니다. 사용자 전용 스크립트나 커스텀 바이너리를 전역에서 실행하려면 ~/.bashrc 파일에서 PATH 환경 변수에 해당 디렉터리를 등록합니다. # ~/.bashrc 파일 하단에 추가 export PATH=$PATH:$HOME/bin:/custom/path # 설정 즉시 적용 source ~/.bashrc 시스템 진단 및 파일 시스템 기본 명령 stty -a: 터미널 특수 제어 문자(시그널 인터럽트 단축키 등)의 매핑 값을 확인합니다. strace <실행파일>: 실행 바이너리가 호출하는 시스템 콜과 시그널을 라인 단위로 추적하여 런타임 문제를 진단합니다. getconf: 운영체제의 시스템 환경 변수 및 하드웨어 구성 값을 조회합니다. getconf LONG_BIT: 시스템 아키텍처가 64비트인지(64) 32비트인지(32) 반환합니다. ldd <실행파일>: 동적 링크 바이너리가 의존하는 공유 라이브러리(*.so) 목록과 로딩 경로를 확인합니다. mkdir -p <디렉터리경로>: 상위 부모 디렉터리가 존재하지 않더라도 계층 전체를 한 번에 생성합니다 (예: mkdir -p A/B/C/D). 텍스트 스트림 조작 sed 스트림 편집기 sed(Stream Editor)는 텍스트 스트림을 한 줄씩 읽어 들여 정규표현식 기반으로 검색, 치환, 삭제를 수행하는 비대화형 편집기입니다. 기본 구문: sed [옵션] '스크립트' [대상파일] 검색 및 특정 행 출력 sed -n '/pattern/p' file.txt: 패턴과 일치하는 줄만 선별하여 출력합니다 (-n은 기본 자동 출력을 억제). 문자열 치환 sed 's/old/new/' file.txt: 각 줄에서 처음 나타난 old를 new로 치환하여 출력합니다 (원본 파일 유지). sed -i 's/old/new/g' file.txt: 파일 내 모든 old를 new로 전역(g) 치환하고 원본 파일에 직접 저장합니다 (-i). sed 's/ */ /g' file.txt: 연속된 두 개 이상의 공백을 단일 공백으로 치환합니다. 행 삭제 sed '/TARGET/d' file.txt: TARGET 문자열이 포함된 줄을 제외하고 출력합니다. sed '/TARGET/!d' file.txt: TARGET 문자열이 포함된 줄만 남기고 나머지는 삭제합니다. sed '1,2d' file.txt: 1행부터 2행까지 삭제합니다. sed '/^$/d' file.txt: 모든 빈 줄(공백 라인)을 삭제합니다. tr 문자 치환 및 삭제 tr은 표준 입력으로부터 문자를 읽어 특정 문자를 변환하거나 제거합니다. 문자 1:1 치환: tr '123' 'abc' (1은 a로, 2는 b로, 3은 c로 변환) 연속된 중복 문자 압축: tr -s ' ' (연속된 공백을 단일 공백으로 압축) 문자 세트 제외 후 치환: tr -c '0-9\n' ' ' (숫자와 개행을 제외한 모든 문자를 공백으로 치환) 특정 문자 삭제: tr -d '\r' (Windows 개행 문자 \r 제거) 아카이브 및 압축 관리 tar 및 deb 압축 해제 tar -cvf <아카이브.tar> <대상디렉터리>: 파일을 tar 아카이브로 묶습니다. tar -xvf <아카이브.tar>: tar 아카이브를 현재 디렉터리에 해제합니다. tar -zcvf <압축파일.tar.gz> <대상디렉터리>: tar 아카이브 묶기 및 gzip 압축을 동시에 수행합니다. tar -zxvf <압축파일.tar.gz>: gzip 압축된 tar.gz 아카이브를 해제합니다. dpkg -x <패키지.deb> <추출경로>: deb 패키지 파일을 설치하지 않고 지정 디렉터리에 내부 파일만 압축 해제합니다. tar 압축 관련 트러블슈팅 .tar.xz 형식 파일 해제 시 다음과 같은 오류가 발생할 수 있습니다. tar (child): xz: Cannot exec: No such file or directory 해결 방법: sudo apt-get install xz-utils 패키지를 설치하여 xz 디컴프레서를 시스템에 갖추어야 합니다. 바이너리 및 파일 속성 분석 파일 기본 정보 조회 (file, wc, xxd) wc <파일>: 파일의 행 수, 단어 수, 바이트 수를 순서대로 출력합니다 (wc -l, wc -c). xxd <바이너리파일>: 바이너리 파일의 16진수 헥스덤프(Hexdump)와 ASCII 텍스트를 나란히 출력합니다. file <파일명>: 파일의 매직 넘버(Magic Number)를 검사하여 ELF 바이너리, 쉘 스크립트, 텍스트, 심볼릭 링크 등의 실제 포맷을 판별합니다. $ file /bin/ls /bin/ls: ELF 64-bit LSB shared object, x86-64, dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2 ELF 바이너리 분석 (readelf, objdump) readelf -h <바이너리>: ELF 헤더 정보(아키텍처, 엔트리 포인트 주소 등)를 출력합니다. readelf -s <바이너리>: 바이너리에 정의된 함수 및 변수 심볼 테이블(Symbol Table)을 출력합니다. readelf -S <바이너리>: .text, .data, .bss, .rodata 등 섹션 헤더 배치 및 플래그를 출력합니다. objdump -d <바이너리>: 기계어 코드 영역(.text)을 디스어셈블하여 x86-64 어셈블리어 코드로 출력합니다. objdump -h <바이너리>: 섹션의 가상 메모리 주소(VMA), 로드 메모리 주소(LMA), 크기 및 파일 오프셋을 확인합니다. 입출력 리다이렉션과 파이프라인 명령어 실행 시 발생하는 표준 스트림(stdin: 0, stdout: 1, stderr: 2)의 방향을 제어합니다. CMD > file: 표준 출력을 파일에 새로 저장합니다 (기존 내용 덮어쓰기). CMD >> file: 표준 출력을 파일 끝에 추가(Append)합니다. CMD 2> error.log: 표준 에러만 선별하여 error.log 파일에 저장합니다. CMD > file 2>&1: 표준 출력과 표준 에러를 동일한 파일에 한 번에 기록합니다. CMD > /dev/null 2>&1: 모든 출력과 에러를 버려 콘솔 출력을 완전히 차단합니다. CMD1 | CMD2: CMD1의 표준 출력을 CMD2의 표준 입력으로 파이프라이닝합니다. 쉘 메타문자 (Metacharacters) $: 환경 변수 또는 쉘 매개변수 참조 (echo $PATH) &&: 논리 AND 연산자로, 앞선 명령어가 성공(종료 코드 0)할 때만 다음 명령어를 실행합니다 (make && make install). ||: 논리 OR 연산자로, 앞선 명령어가 실패(종료 코드 비정상)했을 때만 다음 명령어를 실행합니다. ;: 단순 명령어 순차 구분자로 앞 명령어의 성공/실패와 무관하게 연이어 실행합니다. |: 파이프 연산자 *: 와일드카드 문자 (ls *.txt)

      우분투 apt 및 dpkg errorcode(1) 충돌 오류 원인과 복구 해결법

      우분투 apt 및 dpkg 오류 트러블슈팅 장애 발생 배경 Linux 서버에 개발 환경을 구성하던 중 패키지 설정이 꼬여 원격으로 외부 지원을 요청하였으나, 작업 과정에서 시스템 파일이 잘못 수정되어 APT 패키지 매니저가 완전히 동작을 멈추는 장애가 발생하였습니다. 본 글에서는 해당 장애의 발생 원인과 복구 절차를 정리합니다. 오류 원인 분석 /bin 디렉터리 내의 파이썬 실행 바이너리(python)를 강제로 임의 삭제한 것이 주원인으로 분석되었습니다. 패키지 의존성이 꼬인 상태에서 sudo apt-get upgrade 명령을 무리하게 남용하여 의존성 충돌이 가중되었습니다. 우분투의 다수 시스템 패키지 관리 스크립트(py3compile, py3clean)는 시스템 기본 파이썬 인터프리터에 의존하므로, 파이썬 인터프리터가 부재하면 패키지 설정 단계에서 치명적인 실패가 발생합니다. 장애 현상 apt install 또는 apt remove 명령을 실행할 때마다 py3compile, py3clean 단계에서 예외가 발생하였습니다. APT 작업 시 다음과 같은 에러가 반복 출력되며 정상적인 패키지 작업이 중단되었습니다. /usr/bin/dpkg returned an error code (1) apt-get install -f (broken dependency fix) 명령을 시도해도 동일한 에러 코드를 반환하며 복구되지 않았습니다. 단계별 복구 및 해결 방법 파이썬 환경 임시 복구 파이썬 실행 바이너리가 소실되어 관련 에러가 발생했으므로, 소스코드를 직접 빌드하거나 유효한 파이썬 바이너리를 다운로드하여 /usr/bin/python3 심볼릭 링크를 임시 복구하였습니다. 손상된 dpkg 패키지 메타데이터 확인 /var/lib/dpkg/info/ 디렉터리에는 시스템에 설치된 각 패키지의 설치/삭제 스크립트(*.postinst, *.prerm 등)가 저장되어 있습니다. 오류 로그에 명시된 특정 문제 패키지 목록을 파악한 후, 해당 패키지와 연관된 스크립트 파일을 안전하게 백업 및 삭제하였습니다. sudo rm /var/lib/dpkg/info/<문제가_발생한_패키지_이름>.* dpkg 상태 재구성 손상된 스크립트를 제거한 후 다음 명령으로 미완료 상태의 패키지 구성을 재설정하였습니다. sudo dpkg --configure -a APT 의존성 최종 정리 dpkg 재구성을 반복 수행하여 에러가 더 이상 발생하지 않을 때까지 문제 패키지를 정리한 후 정상적인 패키지 관리가 가능해졌습니다. sudo apt-get update && sudo apt-get -f install 교훈 및 요약 /bin, /usr/bin 등 운영체제 핵심 실행 파일이 위치한 디렉터리의 파일을 수동으로 임의 삭제하면 패키지 매니저 전체가 손상될 수 있으므로 절대 임의 삭제하지 말아야 합니다. 설치된 패키지 메타 정보는 /var/lib/dpkg/info/ 경로에 저장되며, 개별 패키지 스크립트 결함 시 해당 경로를 점검할 수 있습니다. 의존성 충돌 및 패키지 설치 중단 상태는 dpkg --configure -a 명령어로 재설정할 수 있습니다.
